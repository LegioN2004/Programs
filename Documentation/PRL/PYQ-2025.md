# Q 3) a) Define an MDP, including its key components. `[M: 3]` — [5.1](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#51-define-an-mdp-and-its-key-components-m-3)

A **Markov Decision Process (MDP)** is the standard mathematical framework used in Reinforcement Learning to model sequential decision-making problems, where an agent interacts with an environment step by step to achieve a goal. An MDP follows the **Markov Property**, which simply means the future depends *only* on the current state and action—not on how the agent got there (the past history does not matter).

Mathematically, an MDP is defined by a 5-tuple:

$$(S, A, P, R, \gamma)$$

**Key Components of an MDP:**

1. **State Space ($S$):** The set of all possible situations or positions the agent can be in. A state $s \in S$ is a snapshot of everything the agent can observe at a given moment (for example, the agent's current tile on a gridworld).
2. **Action Space ($A$):** The set of all possible moves or decisions the agent can take to affect the environment (for example, moving Left, Right, Up, or Down).
3. **Transition Probability Function ($P$):** The "rules" or physics of the environment. Written as $P(s' \mid s, a) = \Pr(S_{t+1} = s' \mid S_t = s, A_t = a)$, it tells us the probability of landing in a new state $s'$ after taking action $a$ in state $s$. This captures any randomness in the environment (such as slipping on ice).
4. **Reward Function ($R$):** A numerical feedback signal given by the environment after each action, written as $R(s, a, s')$. It assigns a positive score for good outcomes (like reaching a goal) and a negative score for mistakes or delays.
5. **Discount Factor ($\gamma$):** A number in the range $[0, 1]$ (typically $\gamma \in [0, 1)$) that controls how much the agent values future rewards compared to immediate ones. A value near $0$ makes the agent short-sighted (only caring about instant reward), while a value near $1$ makes it far-sighted and ensures that total rewards in long or continuing tasks stay finite.

Using these five components, the ultimate objective of solving an MDP is to find a policy $\pi$ (a strategy for choosing actions) that maximizes the agent's total expected discounted reward over time.

# Q 3) b) — [5.2](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#52-formal-5-tuple-description-of-an-mdp-s-a-p-r-gamma-m-3)

A **Markov Decision Process (MDP)** is formally defined by the 5-tuple **$(S, A, P, R, \gamma)$**, which provides the complete mathematical blueprint of a Reinforcement Learning problem. Each component describes a specific part of how the agent interacts with the environment:

1. **$S$ — State Space:**  
   The set of all possible situations, positions, or configurations the agent can be in. A state $s \in S$ acts as a snapshot of everything the agent observes at a given moment (for example, the 16 tiles on a $4 \times 4$ FrozenLake grid or the sensor readings of a drone).

2. **$A$ — Action Space:**  
   The set of all valid moves or decisions the agent can choose to influence the environment. Depending on the problem, actions can be discrete (such as Left, Down, Right, Up) or continuous (such as steering angles).

3. **$P$ — Transition Probability Function:**  
   The "physics" or rules of the environment, written as:

   $$P(s' \mid s, a) = \Pr(S_{t+1} = s' \mid S_t = s, A_t = a)$$

   It specifies the probability of landing in the next state $s'$ when the agent takes action $a$ from state $s$. This accounts for uncertainty or randomness in the world (for instance, slipping sideways on icy tiles instead of moving straight ahead).

4. **$R$ — Reward Function:**  
   A scalar numerical score issued by the environment after each transition, written as $R(s, a, s')$. It tells the agent how good or bad an outcome was—giving positive rewards for reaching goals and negative penalties for crashes, mistakes, or wasting time.

5. **$\gamma$ — Discount Factor:**  
   A scalar value in the range $\gamma \in [0, 1]$ (usually $[0, 1)$) that controls how much the agent values future rewards compared to immediate rewards. A value close to $0$ makes the agent short-sighted (caring only about instant reward), while a value close to $1$ makes it far-sighted and ensures that the total return stays finite in long or continuing tasks.

Together, these five components define the entire decision-making problem, allowing the agent to learn a policy $\pi$ that maximizes its expected cumulative discounted reward over time.

# Q 3) c) Explain policy evaluation, including the Bellman expectation equation for value functions under a given policy. `[M: 3]`

### 1. What is Policy Evaluation?
**Policy Evaluation** (also known as the **Prediction Problem**) is the process of measuring **how good a given policy $\pi$ is**.

Specifically, you are given a **fixed strategy $\pi$** (meaning the agent's behavior is already decided and does not change), and your goal is to calculate the true **state-value function $V_\pi(s)$** for every state $s$—that is, how much total future discounted reward the agent can expect if it starts in state $s$ and follows policy $\pi$.

* **Easy Analogy:** Imagine you already have a fixed set of rules for playing a board game (e.g., *"whenever you have 17 or more points, stop"*). Policy evaluation doesn't try to invent a better strategy; it simply scores every situation on the board to tell you your expected final score under those exact rules.

---

### 2. Bellman Expectation Equation Under Policy $\pi$
The **Bellman Expectation Equation** is the mathematical tool that lets us compute these values. Instead of calculating all future paths out to infinity, it links the value of the **current state** to the value of the **next state** in one simple step:

$$\text{Value of current state} = \text{Expected Immediate Reward} + \gamma \times (\text{Expected Value of Next State})$$

#### A. For the State-Value Function $V_\pi(s)$

$$V_\pi(s) = \sum_{a \in A} \pi(a \mid s) \sum_{s' \in S, \, r} P(s', r \mid s, a) \big[ r + \gamma V_\pi(s') \big]$$

**What each part means in plain English:**
* **$\sum_{a \in A} \pi(a \mid s)$:** Look at every action $a$ you might choose in state $s$, weighted by the probability that policy $\pi$ picks it.
* **$\sum_{s', r} P(s', r \mid s, a)$:** For each action, look at every possible next state $s'$ and reward $r$ you might land on, weighted by the environment's transition probability.
* **$\big[ r + \gamma V_\pi(s') \big]$:** Add the immediate reward $r$ you get right now plus the discounted value $\gamma V_\pi(s')$ of the next state you land in.

#### B. For the Action-Value Function $Q_\pi(s, a)$
Similarly, the Bellman Expectation Equation for scoring a specific state–action pair $(s, a)$ under policy $\pi$ is:

$$Q_\pi(s, a) = \sum_{s' \in S, \, r} P(s', r \mid s, a) \left[ r + \gamma \sum_{a' \in A} \pi(a' \mid s') Q_\pi(s', a') \right]$$

---

### 3. How Policy Evaluation Works in Practice (Iterative Policy Evaluation)
In small MDPs with only 2–3 states, we can solve the Bellman equations directly as a system of linear equations. For larger MDPs, we use **Iterative Policy Evaluation**:

1. **Initialize:** Start with an initial guess $V_0(s) = 0$ for all states (terminal states stay $0$).
2. **Repeat Sweeps:** In each round $k = 0, 1, 2, \dots$, update every state $s \in S$ using the Bellman Expectation Equation as an update rule:

   $$V_{k+1}(s) = \sum_{a \in A} \pi(a \mid s) \sum_{s' \in S, \, r} P(s', r \mid s, a) \big[ r + \gamma V_k(s') \big]$$

3. **Converge & Stop:** As $k$ increases, the numbers settle down and converge to the exact true values $V_\pi(s)$. We stop once the largest change across all states becomes tiny ($\max_s \lvert V_{k+1}(s) - V_k(s) \rvert < \theta$).

# Q 3) d) Describe the difference between policy evaluation and policy control. `[M: 3]`

In Reinforcement Learning, solving an MDP comes down to two distinct questions: **"How good is my current plan?"** and **"What is the best possible plan?"** These two questions correspond to **Policy Evaluation** and **Policy Control**.

### 1. Policy Evaluation ("Prediction")
* **Goal:** You are given a **fixed policy $\pi$** (a strategy that is already chosen). Your only job is to **score how good it is** by computing its state-value function $V_\pi(s)$ or action-value function $Q_\pi(s, a)$.
* **Does the policy change?** **No.** The agent keeps following $\pi$ blindly without trying to fix bad moves.
* **Equation used:** Uses the **Bellman Expectation Equation** (averaging over the probabilities $\pi(a \mid s)$):

$$V_\pi(s) = \sum_{a \in A} \pi(a \mid s) \sum_{s', r} P(s', r \mid s, a) \big[ r + \gamma V_\pi(s') \big]$$

* **Analogy:** Grading a student's test—you are just calculating the score, not rewriting the answers.

---

### 2. Policy Control ("Optimization")
* **Goal:** You want to **find the best possible policy $\pi^*$** (optimal strategy) that earns the maximum possible total reward, along with the optimal value functions $V^*(s)$ and $Q^*(s, a)$.
* **Does the policy change?** **Yes.** The agent actively changes and improves its choices by picking the best actions ($\arg\max_a$).
* **Equation used:** Uses the **Bellman Optimality Equation** (taking the maximum $\max_a$ instead of averaging):

$$V^*(s) = \max_{a \in A} \sum_{s', r} P(s', r \mid s, a) \big[ r + \gamma V^*(s') \big]$$

* **Analogy:** Coaching a player—constantly tweaking their moves until they play an unbeatable game.

---

### How They Work Together
Policy Evaluation and Policy Control work hand in hand inside **Policy Iteration / Generalized Policy Iteration (GPI)**:
1. First, **Policy Evaluation** measures how well the current policy is performing.
2. Next, **Policy Control** uses those scores to greedily pick better actions ($\pi \to \pi'$).
3. Repeating these two steps leads straight to the optimal policy $\pi^*$.

### Side-by-Side Comparison

| Feature | Policy Evaluation (Prediction) | Policy Control (Optimization) |
| :--- | :--- | :--- |
| **Main Question** | *"How much reward will I get if I follow $\pi$?"* | *"What is the best strategy $\pi^*$ to maximize reward?"* |
| **Input / Output** | Given $\pi$ $\longrightarrow$ Find $V_\pi$ or $Q_\pi$. | Find optimal $\pi^*$ (and $V^*$ / $Q^*$). |
| **Policy Status** | **Fixed** (never changes). | **Updated** (improved repeatedly). |
| **Math Operator** | Expectation / **Average** ($\sum_a \pi(a \mid s)$). | Optimization / **Maximum** ($\max_a$). |
| **Bellman Equation** | Bellman Expectation Equation. | Bellman Optimality Equation. |

# Q 3) e) Outline the basic principles of Dynamic Programming (DP) methods in RL, such as policy iteration and value iteration, including their iterative update rules and convergence conditions. `[M: 3]`

### 1. Basic Principles of Dynamic Programming (DP) in RL
**Dynamic Programming (DP)** is a collection of algorithms used to find optimal policies when we have a **complete model of the environment** (meaning we know all transition probabilities $P(s', r \mid s, a)$ and rewards). DP relies on three core principles:

1. **Optimal Substructure (Bellman's Principle of Optimality):** A big sequential decision problem can be broken into two easier pieces: *(best immediate step right now) + (optimal solution from the next state onward)*.
2. **Overlapping Subproblems (Reuse Stored Values):** Instead of recalculating future paths from scratch every time, DP stores state values $V(s)$ in a table and reuses them.
3. **Bootstrapping & Full-Width Backups:** DP updates each state's value using the current estimates of all its possible next states (full-width lookahead over every action and outcome).

---

### 2. Policy Iteration (Evaluate $\rightarrow$ Improve Loop)
Policy Iteration finds $\pi^*$ by repeating two steps until the policy stops changing:

* **Step 1 — Iterative Policy Evaluation:** Given current policy $\pi_k$, repeatedly update $V(s)$ until it settles on $V_{\pi_k}(s)$:

  $$V_{i+1}(s) = \sum_{a \in A} \pi_k(a \mid s) \sum_{s', r} P(s', r \mid s, a) \big[ r + \gamma V_i(s') \big]$$

* **Step 2 — Greedy Policy Improvement:** Pick the best action in every state to form a better policy $\pi_{k+1}$:

  $$\pi_{k+1}(s) = \arg\max_{a \in A} \sum_{s', r} P(s', r \mid s, a) \big[ r + \gamma V_{\pi_k}(s') \big]$$

* **Convergence Condition:** Stops when the policy **no longer changes** ($\pi_{k+1}(s) = \pi_k(s)$ for all $s \in S$). Because a finite MDP has finitely many deterministic policies and each step strictly improves the policy, it is guaranteed to converge to $\pi^*$ in a finite number of iterations.

---

### 3. Value Iteration (Direct Optimal Updates)
Instead of waiting for full Policy Evaluation on every loop, **Value Iteration** combines evaluation and improvement into **one single greedy update** using the Bellman Optimality Equation:

* **Iterative Update Rule:**

  $$V_{k+1}(s) = \max_{a \in A} \sum_{s', r} P(s', r \mid s, a) \big[ r + \gamma V_k(s') \big]$$

* **Deriving the Optimal Policy:** Once $V_k$ converges to $V^*$, extract $\pi^*$ with one greedy pass:

  $$\pi^*(s) = \arg\max_{a \in A} \sum_{s', r} P(s', r \mid s, a) \big[ r + \gamma V^*(s') \big]$$

* **Convergence Condition:** Stops when the maximum change across all states drops below a tiny threshold $\theta > 0$:

  $$\max_{s \in S} \lvert V_{k+1}(s) - V_k(s) \rvert < \theta$$

  *(Guaranteed by the **Banach Contraction Mapping Theorem** whenever $\gamma < 1$, or in episodic tasks where all policies eventually terminate).*

---

# Q 3) g) Evaluate the limitations of Dynamic Programming methods in large-scale MDPs with high-dimensional state spaces. Create a modified DP algorithm incorporating prioritized sweeping to improve efficiency, and justify how it reduces computational complexity while preserving optimality guarantees. `[M: 2]`

### 1. Limitations of DP in Large-Scale High-Dimensional MDPs
* **Curse of Dimensionality:** As the number of state variables grows (e.g., a robot with 10 joint angles and velocities), the total number of states $\lvert S \rvert$ explodes exponentially, making it impossible to store a lookup table in memory.
* **Wasted Full-Sweep Computation:** Standard Value Iteration costs $O(\lvert S \rvert^2 \lvert A \rvert)$ per full sweep and blindly updates *every* state equally—even millions of states whose values have zero change or lie far away from rewards.

---

### 2. Modified DP Algorithm with Prioritized Sweeping
Instead of sweeping every state in fixed order, we maintain a **Priority Queue (Max-Heap)** ordered by each state's **Bellman Error** $\lvert \Delta(s) \rvert$:

1. **Initialize:** Set $V(s) = 0$ for all $s$; compute initial Bellman errors and insert states with error $> \theta$ into priority queue $PQ$.
2. **Loop while $PQ$ is not empty:**
   * Pop the state $s$ with the **highest priority** (largest $\lvert \Delta(s) \rvert$).
   * Update $V(s) \leftarrow \max_a \sum_{s', r} P(s', r \mid s, a) \big[ r + \gamma V(s') \big]$.
   * For every **predecessor state** $\bar{s}$ (states that have a transition leading into $s$):
     * Recompute $\Delta(\bar{s}) = \left\lvert \max_a \sum_{s', r} P(s', r \mid \bar{s}, a)[r + \gamma V(s')] - V(\bar{s}) \right\rvert$.
     * If $\Delta(\bar{s}) > \theta$, insert or update $\bar{s}$ in $PQ$ with priority $\Delta(\bar{s})$.

---

### 3. Justification (Complexity & Optimality)
* **Reduces Computational Complexity:** By updating only the states with the largest errors and tracing backward strictly through their predecessors, Prioritized Sweeping skips irrelevant regions of the state space. Each update only touches predecessors ($O(k \log \lvert S \rvert)$ heap operations) rather than wasting $O(\lvert S \rvert^2 \lvert A \rvert)$ on full sweeps, speeding up convergence dramatically.
* **Preserves Optimality Guarantees:** Under **Asynchronous Value Iteration** theory, updates do not need to occur in full synchronous sweeps—as long as every state whose Bellman error exceeds $\theta$ continues to be selected and updated, the Bellman Optimality operator remains a $\gamma$-contraction ($\gamma < 1$) and still converges to the exact same unique optimal value function $V^*$.

# Q 4) a) Define the Markov property and explain its significance in MDPs. `[M: 3]`

### 1. What is the Markov Property?
The **Markov Property** (also called the *"memoryless property"*) states that **the future depends only on the present state and action—not on the past history** of how you got there.

* **Easy Analogy:** Imagine walking into the middle of a **Chess** game. To decide the best next move, you only need to look at where the pieces are sitting on the board **right now** ($S_t$). You do *not* need a video replay of all the moves that happened 10 minutes ago—everything relevant from the past is already captured in the current board position!

#### Mathematical Definition
For any state $S_t$ and action $A_t$, the probability of landing in the next state $s'$ and receiving reward $r$ is the same whether you look at the **entire past history** or **just the current state and action**:

$$\Pr(S_{t+1} = s', R_{t+1} = r \mid S_t, A_t, S_{t-1}, A_{t-1}, \dots, S_0, A_0) = \Pr(S_{t+1} = s', R_{t+1} = r \mid S_t, A_t)$$

When an environment's states satisfy this property, we call it a **Markov State**, and the problem can be modeled as a **Markov Decision Process (MDP)**.

---

### 2. Significance of the Markov Property in MDPs
Why is this simple rule so important in Reinforcement Learning?

1. **No Need to Store Long Histories (Memory Efficiency):**
   Without the Markov property, an agent would have to remember every single step since the beginning of time just to make one decision. Because the current state $S_t$ summarizes all useful past information, the agent only needs to track $S_t$.
2. **Enables the Bellman Equations (Divide and Conquer):**
   Because the future only depends on where you are right now, we can split the total future reward into **(Immediate Reward) + (Discounted Value of the Next State)**. This recursive breakdown is what gives us the Bellman Equations, which power Dynamic Programming, TD learning, and Q-learning.
3. **Simple Policies:**
   A policy $\pi(a \mid s)$ only needs the current state $s$ as input—not a complicated sequence of past states—making optimal decision-making clean and fast.
4. **Convergence Guarantees:**
   Classic RL algorithms (Value Iteration, Policy Iteration, TD(0), SARSA, Q-Learning) are mathematically guaranteed to converge to the true optimal solution **only** when the state satisfies the Markov property.

# Q 4) b) List and describe the tuple components of an MDP $(S, A, P, R, \gamma)$. `[M: 3]` — [5.2](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#52-formal-5-tuple-description-of-an-mdp-s-a-p-r-gamma-m-3)

A **Markov Decision Process (MDP)** is the standard mathematical blueprint used to model decision-making problems in Reinforcement Learning. It is formally defined as a **5-tuple**:

$$(S, A, P, R, \gamma)$$

Each component represents one building block of the interaction between the **Agent** and the **Environment**:

1. **$S$ — State Space:**  
   The set of all possible situations, positions, or configurations the agent can be in. A single state $s \in S$ acts as a complete snapshot of what is happening right now (for example, the 16 tiles on a $4 \times 4$ gridworld or a robot's battery level).

2. **$A$ — Action Space:**  
   The set of all valid moves or decisions the agent can make to interact with the environment. Actions can be **discrete** (like `Left`, `Right`, `Up`, `Down`) or **continuous** (like turning a steering wheel by $15.5^\circ$).

3. **$P$ — Transition Probability Function:**  
   The "rules" or physics of the environment, written as:

   $$P(s' \mid s, a) = \Pr(S_{t+1} = s' \mid S_t = s, A_t = a)$$

   It tells us the probability of landing in a new state $s'$ when the agent is in state $s$ and picks action $a$. This captures any uncertainty or randomness in the world (such as a robot's wheels slipping on a wet floor).

4. **$R$ — Reward Function:**  
   A numerical feedback signal (score) given by the environment after a transition, written as $R(s, a, s')$ or $\mathbb{E}[R_{t+1} \mid S_t=s, A_t=a]$. It gives **positive rewards** for good outcomes (reaching a goal) and **negative penalties** for mistakes, crashes, or delays.

5. **$\gamma$ — Discount Factor:**  
   A number in the range $\gamma \in [0, 1]$ (typically $[0, 1)$) that decides how much the agent cares about future rewards compared to immediate rewards:
   * **$\gamma \approx 0$ (Short-sighted):** Only cares about instant rewards right now.
   * **$\gamma \approx 1$ (Far-sighted):** Values long-term future rewards almost as much as immediate ones, while still keeping total sums finite in continuing tasks.

### Quick Summary Table

| Symbol | Name | Plain-English Meaning |
| :---: | :--- | :--- |
| **$S$** | **State Space** | All possible situations the agent can be in. |
| **$A$** | **Action Space** | All possible moves the agent can choose from. |
| **$P$** | **Transition Function** | Probability of ending up in next state $s'$ after doing $a$ in $s$. |
| **$R$** | **Reward Function** | Points/score given by the environment after each step. |
| **$\gamma$** | **Discount Factor** | How much future points matter compared to points right now ($0$ to $1$). |

# Q 4) c) Differentiate between episodic and continuing tasks in MDPs, with examples. `[M: 3]`

In Reinforcement Learning, the interaction between an agent and its environment can either have a clear finish line or go on forever. Based on this, tasks in a Markov Decision Process (MDP) are divided into **Episodic Tasks** and **Continuing Tasks**.

### 1. Episodic Tasks
* **What it means:** These are tasks that naturally break down into separate rounds or games called **episodes**. Every episode starts from a starting state, goes through a sequence of steps, and ends when the agent reaches a special **terminal state** (the finish line).
* **Fresh start:** Once an episode ends, the environment resets completely to a new starting state, and the next episode begins independently.
* **Return formula:** Because there is a fixed final time step $T$, the total future reward (return $G_t$) is a finite sum:

$$G_t = R_{t+1} + R_{t+2} + R_{t+3} + \dots + R_T$$

* **Discount factor ($\gamma$):** Can be $\gamma = 1$ (no discounting needed since the episode always ends) or $\gamma \in [0, 1)$.
* **Examples:**
  * **Playing Chess or Tic-Tac-Toe:** Every match ends in a win, loss, or draw (terminal state), and the board is reset for the next match.
  * **Navigating a Maze / FrozenLake:** An episode ends as soon as the agent reaches the goal or falls into a hole.

---

### 2. Continuing Tasks
* **What it means:** These are ongoing tasks that **never end**. The agent interacts with the environment continuously without any terminal state or reset.
* **Infinite horizon:** The time step $t$ goes on toward infinity ($T = \infty$).
* **Return formula:** If we simply added all future rewards forever without shrinking them, the sum could become infinite ($\infty$), making it impossible to compare strategies. Therefore, we must use a **discount factor $\gamma \in [0, 1)$** so distant rewards shrink and the total sum stays finite:

$$G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}$$

* **Examples:**
  * **Smart Thermostat / AC Control:** Maintaining a comfortable room temperature 24/7—there is no "game over."
  * **Stock Trading Bot / Server Load Balancing:** Continuously making buy/sell decisions or routing web traffic indefinitely.

---

### Key Differences at a Glance

| Feature | Episodic Tasks | Continuing Tasks |
| :--- | :--- | :--- |
| **Ending** | Has a clear **terminal state** (ends at step $T$). | **Never ends** ($T = \infty$); no terminal state. |
| **Resets** | Resets to a starting state after each episode. | Runs continuously in one single lifelong stream. |
| **Discount Factor ($\gamma$)** | Can be $\gamma = 1$ or $\gamma < 1$. | Must have $\gamma < 1$ (so the infinite sum stays finite). |
| **Return ($G_t$)** | Finite sum up to $T$. | Infinite discounted sum. |
| **Examples** | Chess, Mario levels, Maze navigation. | Thermostat control, Stock trading, Traffic lights. |

# Q 4) d) Explain the concepts of state-value function $V_\pi(s)$ and action-value function $Q_\pi(s,a)$ under a policy $\pi$, including their Bellman equations. `[M: 3]`

To figure out the best strategy (policy $\pi$), a Reinforcement Learning agent needs a way to score how good its situations and choices are. This is done using **Value Functions**, which measure the **expected total future reward**.

### 1. State-Value Function: $V_\pi(s)$
* **Easy meaning:** *"How good is it to be in state $s$?"*
* **Formal definition:** $V_\pi(s)$ is the expected return (total discounted future reward) if the agent **starts in state $s$** and follows **policy $\pi$** from that point onward:

$$V_\pi(s) = \mathbb{E}_\pi \big[ G_t \mid S_t = s \big]$$

* **Example:** In a maze, squares close to the exit have a high $V_\pi(s)$, while squares near a trap have a low $V_\pi(s)$.

#### Bellman Expectation Equation for $V_\pi(s)$
The Bellman equation breaks the value of state $s$ into two simple parts: **(Immediate Reward) + (Discounted Value of the Next State)**.

$$V_\pi(s) = \sum_{a \in A} \pi(a \mid s) \sum_{s' \in S, \, r} P(s', r \mid s, a) \big[ r + \gamma V_\pi(s') \big]$$

* **What it means in words:** Look at every action $a$ that policy $\pi$ might pick in state $s$ (weighted by probability $\pi(a \mid s)$), look at every next state $s'$ and reward $r$ it could lead to (weighted by transition probability $P(s', r \mid s, a)$), and average the immediate reward $r$ plus the discounted value $\gamma V_\pi(s')$ of where you land.

---

### 2. Action-Value Function: $Q_\pi(s, a)$
* **Easy meaning:** *"How good is it to take action $a$ while standing in state $s$?"*
* **Formal definition:** $Q_\pi(s, a)$ is the expected return if the agent **starts in state $s$**, **first takes action $a$**, and *then* follows policy $\pi$ for all future steps:

$$Q_\pi(s, a) = \mathbb{E}_\pi \big[ G_t \mid S_t = s, A_t = a \big]$$

* **Why it is useful:** While $V_\pi(s)$ only scores the room you are in, $Q_\pi(s, a)$ scores each individual door (action) in that room, making it easy to pick the best move.

#### Bellman Expectation Equation for $Q_\pi(s, a)$
Just like $V_\pi(s)$, it splits into immediate reward plus discounted future value of the next state-action pair:

$$Q_\pi(s, a) = \sum_{s' \in S, \, r} P(s', r \mid s, a) \left[ r + \gamma \sum_{a' \in A} \pi(a' \mid s') Q_\pi(s', a') \right]$$

* **Relationship between $V_\pi$ and $Q_\pi$:**
  The value of a state is simply the weighted average of the $Q$-values of all actions available in that state:

$$V_\pi(s) = \sum_{a \in A} \pi(a \mid s) Q_\pi(s, a)$$

---

### Quick Comparison

| Aspect | State-Value Function $V_\pi(s)$ | Action-Value Function $Q_\pi(s, a)$ |
| :--- | :--- | :--- |
| **Question answered** | How good is it to **be in state $s$**? | How good is it to **do action $a$ in state $s$**? |
| **Inputs** | State $s$ only. | Both state $s$ and action $a$. |
| **Use in Control** | Needs transition rules $P$ to choose actions. | Directly picks best action via $\arg\max_a Q_\pi(s,a)$. |

---

# Q 4) e) Describe policy improvement theorem and how it relates to policy control. `[M: 3]`

### 1. What is the Policy Improvement Theorem?
Imagine you already have a routine (policy $\pi$) for going to work, and you know how much time it takes ($V_\pi(s)$). One day, at one specific intersection $s$, you decide to test a **new shortcut** $\pi'(s)$ just for that single step, and then follow your old routine $\pi$ for the rest of the trip.

If taking that one-step shortcut gives you a better (or equal) outcome than your old routine, then **switching to that new choice permanently** will give you a better (or equal) overall policy $\pi'$!

#### Mathematical Statement
Suppose we have two deterministic policies $\pi$ and $\pi'$. If for **every state $s \in S$**:

$$Q_\pi(s, \pi'(s)) \ge V_\pi(s)$$

Then policy $\pi'$ is guaranteed to be **at least as good as (or better than) $\pi$** in every single state:

$$V_{\pi'}(s) \ge V_\pi(s) \quad \forall s \in S$$

Furthermore, if the inequality is **strictly greater** ($>$) for at least one state, then $\pi'$ is **strictly better** than $\pi$ (meaning $V_{\pi'}(s) > V_\pi(s)$ for at least one state).

---

### 2. How Do We Create a Better Policy $\pi'$? (Greedy Improvement)
Instead of guessing a new policy randomly, we look at all actions $a$ in every state $s$ and pick the action with the highest $Q_\pi(s, a)$ value:

$$\pi'(s) = \arg\max_{a \in A} Q_\pi(s, a) = \arg\max_{a \in A} \sum_{s', r} P(s', r \mid s, a) \big[ r + \gamma V_\pi(s') \big]$$

Because taking the maximum is always greater than or equal to the current policy's action, $Q_\pi(s, \pi'(s)) \ge V_\pi(s)$ is **automatically satisfied**!

---

### 3. How It Relates to Policy Control
**Policy Control** means finding the **optimal policy $\pi^*$** (the best possible way to behave). The Policy Improvement Theorem is the engine that makes Policy Control work:

1. **Step-by-step improvement (Policy Iteration):**
   We repeat a two-step cycle called **Generalized Policy Iteration (GPI)**:
   * **Policy Evaluation:** Calculate $V_\pi$ (or $Q_\pi$) for our current policy $\pi$.
   * **Policy Improvement:** Use the Policy Improvement Theorem to greedily update $\pi \to \pi'$.
2. **Guaranteed progress:** Because each improvement step is guaranteed not to make the policy worse, the policy climbs steadily upward:

$$\pi_0 \xrightarrow{\text{improve}} \pi_1 \xrightarrow{\text{improve}} \pi_2 \dots \xrightarrow{\text{improve}} \pi^*$$

3. **Stopping condition (Optimality):** When greedy improvement stops changing the policy (i.e., $V_{\pi'}(s) = V_\pi(s)$ everywhere), the Bellman Optimality Equation holds, which proves we have found the **optimal policy $\pi^*$**!

---

# Q 4) g) Evaluate the scalability issues of tabular Dynamic Programming methods (e.g., value iteration) in MDPs with continuous state spaces or partial observability. Create a hybrid DP approach that integrates function approximation with prioritized experience replay to handle such challenges, and justify its advantages in terms of convergence speed and memory efficiency. `[M: 2]`

### 1. Scalability Issues of Tabular Dynamic Programming
Tabular DP (like Value Iteration) stores a separate entry for every state in a giant lookup table and updates all of them every sweep. This breaks down in two ways:
* **Continuous / Huge State Spaces (Curse of Dimensionality):** Continuous states (like a robot's exact angle, speed, and coordinates) have *infinitely many* values. A table cannot store infinite rows, and sweeping over millions of discretized grid cells takes too much memory and time.
* **Partial Observability (POMDPs):** When sensors cannot see the full true state (e.g., an obstacle hidden behind a wall), identical observations can mean different situations (**state aliasing**). To handle this, tabular DP must track probabilities over all possible hidden states (**belief states**), turning a finite table into a massive continuous space.

---

### 2. Hybrid DP Approach: Function Approximation + Prioritized Experience Replay (PER)
To scale DP to continuous and partially observable problems, we replace the lookup table and full-grid sweeps with a smart hybrid architecture:
1. **Belief / History Encoder + Function Approximation:**
   Instead of a table, feed a short observation history (or recurrent memory like an LSTM) into a parameterized **neural network** $V_\theta(s)$ (or $Q_\theta(s, a)$) to predict values smoothly across continuous states.
2. **Prioritized Experience Replay (PER) Buffer:**
   Store observed transitions $(s_t, a_t, r_{t+1}, s_{t+1})$ in a fixed-size replay buffer. Instead of sweeping every state equally like tabular DP, measure each transition's **Bellman Error** $\lvert \delta_t \rvert = \lvert r + \gamma \max_{a'} Q_\theta(s', a') - Q_\theta(s, a) \rvert$ and sample experiences with larger errors more frequently for updates.

---

### 3. Justification (Convergence Speed & Memory Efficiency)
* **Faster Convergence Speed:** Classic Value Iteration wastes computation re-evaluating boring states whose values have already settled. **Prioritized Experience Replay** focuses updates strictly on high-error, surprising states (like discovering a new reward or boundary), propagating value updates much faster—similar to *Prioritized Sweeping* in DP.
* **High Memory Efficiency:** **Function approximation** compresses millions (or infinite) continuous states into a fixed set of network weights $\theta$, and the **bounded replay buffer** stores only recent/useful experiences instead of an exponentially growing state-transition table.

# Q 5) a) Define Monte Carlo (MC) methods, explaining how they estimate value functions using complete episode returns. `[M: 3]` — [1.1](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#11-monte-carlo-policy-evaluation-learning-without-a-rulebook), [1.2](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#12-first-visit-vs-every-visit-mc)

### What Are Monte Carlo (MC) Methods?
**Monte Carlo (MC) methods** are **model-free** Reinforcement Learning algorithms that learn purely from **experience**—that is, by actually playing through sample episodes (sequences of states, actions, and rewards) without needing to know the environment's transition probabilities $P(s', r \mid s, a)$.

In simple words: **MC learns like a human playing a full board game.** You don't calculate probabilities beforehand; you simply play a bunch of complete games from start to finish, see how many points you scored in each round, and take the average!

---

### How MC Estimates Value Functions Using Complete Returns

Because MC does not know the rules of the world, it waits until an episode **finishes completely** (reaches the terminal state $T$) before learning anything.

1. **Generate an Episode:**
   Follow policy $\pi$ from start to finish:

   $$S_0, A_0, R_1, S_1, A_1, R_2, \dots, S_{T-1}, A_{T-1}, R_T, S_T$$

2. **Compute the Complete Return ($G_t$):**
   Work backward from the end of the episode to calculate the actual discounted total reward collected after visiting state $S_t$:

   $$G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots + \gamma^{T-t-1} R_T$$

3. **Average the Returns (Law of Large Numbers):**
   Since the true state value $V_\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]$ is simply the *expected (average)* return from $s$, MC averages the observed returns across many episodes:
   * **First-Visit MC:** Averages $G_t$ only from the **first time** state $s$ was visited in each episode (statistically unbiased).
   * **Every-Visit MC:** Averages $G_t$ from **every time** state $s$ was visited in an episode.

4. **Incremental Update Rule:**
   Instead of storing a huge list of every past return, MC updates its running average after each visit using:

   $$V(S_t) \leftarrow V(S_t) + \alpha \big[ G_t - V(S_t) \big]$$

   *(where $\alpha = \frac{1}{N(S_t)}$ gives the exact sample average, or a constant $\alpha$ tracks moving targets).*

# Q 5) b) Provide examples of MC prediction and control algorithms. `[M: 3]` — [1.2](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#12-first-visit-vs-every-visit-mc), [1.4](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#14-the-exploration-dilemma--epsilon-greedy), [1.5](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#15-generalized-policy-iteration-gpi-with-monte-carlo)

In Monte Carlo learning, algorithms are grouped into **Prediction** (evaluating how good a given strategy is) and **Control** (finding the best possible strategy).

---

### 1. Examples of MC Prediction Algorithms (Policy Evaluation)
**Goal:** Given a fixed policy $\pi$, estimate the true state values $V_\pi(s)$ (or $Q_\pi(s, a)$).

1. **First-Visit MC Prediction:**
   * **How it works:** Play an episode using $\pi$. Walk backward to calculate returns $G_t$. For each state $s$, look only at the **very first time** $s$ appeared in that episode, add $G_t$ to $Returns(s)$, and set $V(s) = \text{average}(Returns(s))$.
   * **Example:** If an episode visits states $A \to B \to A \to \text{Goal}$, only the return from the first $A$ ($t=0$) is used to update $V(A)$.
   * **Property:** Completely unbiased estimator of $V_\pi(s)$.

2. **Every-Visit MC Prediction:**
   * **How it works:** Similar to First-Visit, except **every single occurrence** of state $s$ within an episode adds its return $G_t$ to the average.
   * **Example:** In $A \to B \to A \to \text{Goal}$, *both* visits to $A$ ($t=0$ and $t=2$) are averaged into $V(A)$.
   * **Property:** Slightly biased for small sample sizes (because visits in the same episode share the same ending), but often achieves lower error in practice.

---

### 2. Examples of MC Control Algorithms (Finding the Optimal Policy $\pi^*$)
**Goal:** Improve the policy step-by-step using action values $Q(s, a)$ (since $V(s)$ alone cannot tell which action to pick without a model).

1. **Monte Carlo with Exploring Starts (MC-ES):**
   * **How it works:** To ensure no action is ignored, every episode is forced to start at a random state-action pair $(S_0, A_0)$ with probability $> 0$. After the first step, the agent plays greedily ($\arg\max_a Q(s,a)$). After the episode finishes, it updates $Q(s,a)$ and immediately makes the policy greedy wrt the new $Q$.
   * **Limitation:** Requires being able to start the game in any arbitrary state-action pair, which is rarely possible in real life.

2. **On-Policy $\epsilon$-Greedy MC Control:**
   * **How it works:** Drops the need for Exploring Starts. The agent uses an **$\epsilon$-soft / $\epsilon$-greedy policy**: most of the time ($1-\epsilon$) it picks the best known action (exploit), and $\epsilon$ of the time it picks a random action (explore) so every action keeps getting tested. After each episode, it updates $Q(s,a)$ and updates the $\epsilon$-greedy probabilities.

3. **Off-Policy MC Control (via Importance Sampling):**
   * **How it works:** Uses **two policies**—an exploratory **behavior policy ($b$)** (e.g., random) to collect episodes, and a greedy **target policy ($\pi$)** that learns the optimal strategy from that data by re-weighting returns using **Importance Sampling ratios**.

---

# Q 5) c) Describe Temporal Difference (TD) learning, including the TD(0) update rule and its bootstrapping nature. `[M: 3]` — [2.1](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#21-from-monte-carlo-to-temporal-difference-td-learning)

### 1. What is Temporal Difference (TD) Learning?
**Temporal Difference (TD) learning** is often described as the central idea of Reinforcement Learning. It combines the best of **Monte Carlo** (model-free learning directly from experience) and **Dynamic Programming** (updating guesses using other guesses).

In Monte Carlo, if you drive to work, you wait until you park at the office before judging whether your route was good or bad.  
In **TD learning**, you **update your estimate after every single step** (at every traffic light!)—without waiting for the episode to finish.

---

### 2. The TD(0) Update Rule
After taking just **one step** ($S_t \xrightarrow{A_t} R_{t+1}, S_{t+1}$), TD(0) updates the value of $S_t$ immediately using:

$$V(S_t) \leftarrow V(S_t) + \alpha \Big[ \underbrace{R_{t+1} + \gamma V(S_{t+1})}_{\text{TD Target}} - V(S_t) \Big]$$

* **$V(S_t)$:** Our old guess for how good state $S_t$ is.
* **$\alpha \in (0, 1]$:** The **learning rate** (step size), controlling how strongly we adjust our old guess toward the new information.
* **$R_{t+1} + \gamma V(S_{t+1})$ (TD Target):** Our updated, better guess of the total return—built from the **actual reward $R_{t+1}$** we just received plus the discounted value of the **next state $S_{t+1}$**.
* **$\delta_t = R_{t+1} + \gamma V(S_{t+1}) - V(S_t)$ (TD Error):** The surprise! It measures the difference between what we actually observed after one step (TD Target) and what we originally expected ($V(S_t)$).

---

### 3. The Bootstrapping Nature of TD
* **What is Bootstrapping?**
  Bootstrapping means **"updating a guess based on another guess"** (rather than waiting for the final true answer).
* **How TD(0) Bootstraps:**
  When updating $V(S_t)$, TD(0) does **not** know the true future rewards beyond $t+1$. Instead, it plugs in its own current estimate **$V(S_{t+1})$** as a stand-in for the entire rest of the episode!
* **Why is this powerful?**
  * You can learn **online** (step by step) even in tasks that never end.
  * You don't have to suffer through noisy long-term randomness at the end of an episode; you learn immediately from every transition.
  * *(Trade-off:)* Because $V(S_{t+1})$ is just an estimate, early TD updates carry a small **initial bias** (unlike MC, which uses the true final return $G_t$).

---

# Q 5) d) Differentiate between on-policy and off-policy including their update equations. `[M: 3]` — [2.2](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#22-behaviour-policy-mu-vs-target-policy-pi), [2.5](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#25-sarsa-vs-q-learning-side-by-side)

In Reinforcement Learning control, an agent needs to both **explore** (try new moves) and **learn the best strategy** (exploit). **On-Policy** and **Off-Policy** describe *how* the agent balances these two roles.

### 1. On-Policy Learning ("Learn from your own actions")
* **Easy meaning:** There is only **one policy $\pi$**. The agent uses $\pi$ (usually $\epsilon$-greedy) to walk around and collect data, *and* it evaluates and improves that exact same policy $\pi$.
* **Analogy:** Learning to cook by following your own recipe (with occasional random experiments) and improving that recipe based on how your own dishes turn out.
* **Update Equations:**
  * **SARSA (On-Policy TD Control):** Uses the action $A_{t+1}$ that the agent *actually chooses next* under its current policy:

    $$Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \Big[ R_{t+1} + \gamma Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t) \Big]$$

  * **On-Policy MC Control:** Uses actual returns $G_t$ generated by the same $\epsilon$-greedy policy $\pi$:

    $$Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \big[ G_t - Q(S_t, A_t) \big]$$

---

### 2. Off-Policy Learning ("Learn by watching someone else")
* **Easy meaning:** Uses **two separate policies**:
  1. **Behavior Policy ($b$):** The exploratory policy that actually moves around and generates data (e.g., $\epsilon$-greedy or random).
  2. **Target Policy ($\pi$):** The smart, purely greedy policy that we actually want to learn and optimize.
* **Analogy:** Watching a chef cook (or watching old game replays) and learning the best strategy for yourself, even if the chef occasionally tries weird risky ingredients.
* **Update Equations:**
  * **Q-Learning (Off-Policy TD Control):** Always assumes the *best possible* greedy next action ($\max_{a'} Q(S_{t+1}, a')$) will be taken, regardless of what exploratory move the behavior policy $b$ actually picks next:

    $$Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \Big[ R_{t+1} + \gamma \max_{a'} Q(S_{t+1}, a') - Q(S_t, A_t) \Big]$$

  * **Off-Policy MC (with Importance Sampling):** Re-weights the return $G_t$ by the **importance sampling ratio** $\rho_{t:T-1} = \prod_{k=t}^{T-1} \frac{\pi(A_k \mid S_k)}{b(A_k \mid S_k)}$ to correct for the difference between $\pi$ and $b$:

    $$V(S_t) \leftarrow V(S_t) + \alpha \big[ \rho_{t:T-1} G_t - V(S_t) \big]$$

---

### Key Differences Summary

| Feature | On-Policy | Off-Policy |
| :--- | :--- | :--- |
| **Number of Policies** | **One** ($\pi$ acts and learns). | **Two** ($b$ acts/explores, $\pi$ learns). |
| **What it learns** | Value of the *near-optimal* exploratory policy (e.g., $\epsilon$-greedy). | Value of the *truly optimal* greedy policy $\pi^*$. |
| **Variance & Stability** | Simpler, lower variance, safer near cliffs/penalties. | Higher variance (in MC); more flexible and reusable data. |
| **Famous Examples** | SARSA, $\epsilon$-greedy MC Control. | Q-Learning, Off-Policy MC, DQN (with replay). |

---

# Q 5) e) Explain the advantages of MC over DP and TD over MC. `[M: 3]` — [1.1](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#11-monte-carlo-policy-evaluation-learning-without-a-rulebook), [2.1](./Gemini-Reinforcement%20Learning%20Masterclass%20From%20PDFs-20261125-0952.md#21-from-monte-carlo-to-temporal-difference-td-learning)

Each family of Reinforcement Learning algorithms fixes major weaknesses in the previous one.

### Part 1: Advantages of Monte Carlo (MC) over Dynamic Programming (DP)
1. **Model-Free (No Rules Needed):**
   DP requires knowing the *complete transition model* $P(s', r \mid s, a)$ of the environment, which is rarely available in real-world problems (like robotics or stock markets). MC needs **zero knowledge of the model**—it learns purely from sample episodes.
2. **Learns from Actual or Simulated Experience:**
   Instead of doing heavy mathematical probability sums, MC can learn directly from real-world trials or a simulator (e.g., playing thousands of Blackjack hands).
3. **Focuses on Relevant States (No Full Sweeps):**
   DP must sweep through *every single state* in the entire state space on each iteration, which fails on huge problems. MC can estimate the value of just **one or a few states of interest** independently by starting episodes from them.
4. **No Bootstrapping Bias:**
   Because MC uses true complete returns $G_t$, estimates for a state don't depend on inaccurate guesses of neighboring states.

---

### Part 2: Advantages of Temporal Difference (TD) over Monte Carlo (MC)
1. **Online, Step-by-Step Learning (No Waiting):**
   MC must wait until an entire episode ends before making a single update. TD updates **immediately after every step**, making it much faster to react in long episodes.
2. **Works on Continuing (Non-Terminating) Tasks:**
   MC **cannot** be used on tasks that never end (since $G_t$ is never finished!). Because TD only looks one step ahead ($R_{t+1} + \gamma V(S_{t+1})$), it works effortlessly on continuing tasks.
3. **Much Lower Variance:**
   MC's return $G_t$ depends on *every* random action and transition until the end of the game, creating noisy high-variance updates. TD only depends on **one random step** ($R_{t+1}, S_{t+1}$), giving much smoother, lower-variance learning.
4. **Faster Convergence in Practice:**
   Because TD updates immediately and shares information step-by-step via bootstrapping, it usually learns good value estimates in fewer episodes than MC.

---

# Q 5) g) Evaluate the trade-offs between Monte Carlo methods and Temporal Difference learning in terms of bias-variance, sample efficiency, and handling non-stationary environments. Create a hybrid algorithm combining MC's unbiased estimates with TD's bootstrapping to optimize for partially observable MDPs, and justify its improved performance in exploration-heavy tasks. `[M: 2]`

### 1. Trade-Offs Between Monte Carlo (MC) and Temporal Difference (TD)

| Dimension | Monte Carlo (MC) | Temporal Difference (TD) |
| :--- | :--- | :--- |
| **Bias vs. Variance** | **Zero bias, high variance** (uses true full returns $G_t$, which accumulate randomness over the whole episode). | **Some bias, low variance** (bootstraps on estimates $V(S_{t+1})$, so only one step of randomness enters). |
| **Sample Efficiency** | **Lower efficiency**—must wait for full episodes and ignores step-by-step transitions; cannot learn before terminal state. | **Higher efficiency**—learns online at every single step and propagates value rapidly across connected states. |
| **Non-Stationary Environments** | **Better with partial observability / non-Markovian states** (doesn't rely on the Markov assumption because it doesn't bootstrap), though constant $\alpha$ is needed if dynamics change. | **More sensitive** if states lack the Markov property (aliasing corrupts $V(S_{t+1})$), though constant-$\alpha$ TD adapts faster online when rewards/rules drift. |

---

### 2. Hybrid Algorithm for Partially Observable MDPs (POMDPs)
We can blend the strengths of MC and TD using a **History-Augmented $n$-Step $\text{TD}(\lambda)$ (or Memory-Based Eligibility Trace) Algorithm**:

1. **Belief / Observation-History State ($h_t$):**
   In a POMDP, a single observation is ambiguous. Feed recent observations $(o_{t-k}, \dots, o_t)$ through a recurrent encoder (e.g., GRU/LSTM) so $h_t$ restores approximate Markov context.
2. **$\lambda$-Return Target (Blending TD & MC):**
   Instead of pure 1-step TD ($\lambda = 0$) or pure full-episode MC ($\lambda = 1$), compute a **weighted blend of $n$-step returns**:

   $$G_t^\lambda = (1 - \lambda) \sum_{n=1}^{\infty} \lambda^{n-1} G_t^{(n)}$$

   *(where short-step returns provide TD's fast bootstrapping, and longer $n$-step rollouts inject MC's unbiased long-horizon credit assignment).*
3. **Update using Eligibility Traces ($e_t$):**
   Maintain decaying traces $e_t(h)$ so whenever a surprise TD error $\delta_t$ happens, credit flows smoothly backward across the recent trajectory.

---

### 3. Why This Excels in Exploration-Heavy Tasks
* **Handles Delayed Rewards & Aliasing:** In exploration-heavy POMDPs (like searching a foggy maze for a key before opening a door), pure 1-step TD struggles because hidden-state ambiguity causes bootstrapping errors. Mixing in multi-step MC returns bridges long gaps between picking up the key and opening the door without bias.
* **Fast Credit Assignment:** Unlike pure MC—which wastes exploration steps by waiting until the end of long, wandering episodes—TD bootstrapping and eligibility traces update values *immediately* whenever an exploratory step finds a new reward, accelerating learning across large unknown areas.
